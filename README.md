# SiteWatch — простая версия

Учебный сервис мониторинга сайтов на **Nuxt / Vue, TypeScript, Prisma и SQLite**.
Одна страница: добавление сайтов, статусы, пауза и история выбранного монитора.

## Запуск — две команды

Установите **Node.js 24 LTS**. Распакуйте архив **в новую папку**, откройте её в VS Code и запустите терминал в папке с `package.json`:

```bash
npm install
npm run dev
```

Откройте **http://localhost:3000**.

При `npm install` автоматически создаются файл базы `prisma/dev.db`, таблицы и Prisma Client.
При первом запуске сервера автоматически создаётся один учебный пользователь «Студент».
Для последующих запусков достаточно **`npm run dev`**.

База — файл `prisma/dev.db`; её данные сохраняются при перезапуске и повторной установке зависимостей.
Чтобы перенести данные, остановите приложение и скопируйте этот файл вместе с проектом.
В архиве база не приложена: она создаётся у вас, без чужих или выдуманных записей.

Это отдельная упрощённая версия: она не переносит данные из старой PostgreSQL-базы.
Старую папку проекта можно сохранить рядом; накладывать новый архив поверх неё не нужно.

## Как пользоваться

1. Добавьте название, публичный HTTP(S) URL и интервал проверки.
2. Дождитесь первой автоматической проверки. Обновление интерфейса происходит каждые 5 секунд.
3. Нажмите «История» или название сайта — ниже списка откроются результаты и статистика.
4. Выберите период: 24 часа, 7 дней или 30 дней. В истории — по 10 записей на странице.
5. «Пауза» останавливает проверки. «Продолжить» возобновляет их.
6. Кнопка удаления находится в истории. При удалении также удаляются проверки и события этого сайта.

Название, URL и интервал задаются при добавлении. Формы редактирования в этой версии нет: для других настроек создайте новый монитор.

## Что упростилось

- PostgreSQL заменён локальной SQLite-базой; Docker удалён.
- Убраны регистрация, пароли, сессии, авторизация и разделение данных по аккаунтам.
- Сущность `User` сохранена: все мониторы связаны с одним учебным пользователем.
- Одна страница вместо нескольких; убраны поиск, фильтры и расширенные настройки.
- Обычный CSS без UI-библиотек; компактные компоненты Vue.
- Не нужны настройки подключения или секретные ключи.

Проект рассчитан на локальную демонстрацию одним пользователем. `npm run dev` слушает `127.0.0.1`.
Авторизации нет: не размещайте эту версию как публичный многопользовательский сервис.
Если преподаватель отдельно требует регистрацию и вход, эта версия такое дополнительное требование не покрывает.

## Соответствие заданию

| Требование | Где и как реализовано |
| --- | --- |
| Monitor: URL, название, интервал, пользователь, активность | Модель `Monitor` и форма добавления; пауза/возобновление |
| Check: монитор, дата, статус-код, время, размер | Модель `Check`; запись результата каждого запроса |
| User | Один автоматически создаваемый учебный пользователь, связанный с мониторами |
| Notification: монитор, канал, событие | Запись с каналом `log`, новым статусом и датой |
| Проверки по расписанию через setInterval | `server/plugins/checker.ts`, проход раз в секунду |
| Ограничение конкурентности | Пул максимум из 5 работников в `checker-core.ts` |
| История с пагинацией | API возвращает по 10 результатов на страницу |
| Аптайм за период | Успешные проверки / все проверки за выбранный период × 100% |
| Уведомление о смене статуса | Запись в базе и сообщение в терминале при UP → DOWN или DOWN → UP |

Webhook не добавлен, поскольку он опционален. Обязательное уведомление через лог работает.

## Логика проверок

- Сервер выбирает активные мониторы, для которых истёк интервал с момента завершения последней проверки.
- Один проход не запускается поверх предыдущего. Одновременно выполняется не больше 5 HTTP-запросов.
- При большой очереди фактическая проверка может произойти позже указанного интервала.
- GET-запрос возвращает HTTP 200–399 — сайт доступен. HTTP 400–599, ошибка сети или таймаут — недоступен.
- Переходы HTTP обрабатываются до 5 раз. В базу попадает код и размер финального ответа.
- Размер — прочитанные байты тела ответа, без заголовков; отклик — длительность до окончания чтения или до ошибки.
- HTTP-проверка ограничена таймером 10 секунд; DNS — отдельным ожиданием до 3 секунд.
- Ответ больше 5 МиБ считается ошибкой. При незавершённом ответе размер — «—».
- Локальные/частные адреса запрещены; поддерживаются публичные сайты. Их DNS-адрес проверяется при добавлении и перед запросами.
- Первый результат меняет UNKNOWN на UP/DOWN без уведомления. Дальше уведомления создаются только при смене известного статуса.
- Пауза сама по себе не является сбоем и не создаёт уведомления.
- Проверки выполняются, пока работает Node.js-сервер, даже если браузер закрыт. После остановки сервера проверки не выполняются и не создаются задним числом.
- Один экземпляр сервера: многопроцессный запуск для этой простой версии не предусмотрен.

Аптайм — оценка **по числу проверок**, а не точное количество секунд работы. Если проверок за период нет, показывается «—», а не 0% или 100%.
Паузы и время остановки сервера не входят в знаменатель. Средний отклик включает все проверки с измеренным временем, в том числе ошибки.
Даты в интерфейсе выводятся в UTC.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `app/pages/index.vue` | Форма, список сайтов, кнопки паузы и выбора истории |
| `app/components/MonitorDetails.vue` | Статистика, таблица истории, пагинация, события и удаление |
| `app/components/StatusBadge.vue` | Цветная подпись статуса |
| `app/assets/css/main.css` | Оформление и адаптация к узкому экрану |
| `prisma/schema.prisma` | Четыре модели и связи |
| `prisma.config.ts` | Путь к локальной SQLite-базе для Prisma CLI |
| `scripts/create-db.mjs` | Создание пустого файла БД без удаления существующих данных |
| `server/utils/prisma.ts` | Подключение к SQLite и создание учебного пользователя |
| `server/plugins/checker.ts` | Запуск таймера |
| `server/utils/checker.ts` | Расписание, сохранение результатов и уведомлений |
| `server/utils/checker-core.ts` | Ограничение конкурентности и формула аптайма |
| `server/utils/probe.ts` | HTTP-запрос, таймауты и ограничения адресов/ответов |
| `server/utils/validation.ts` | Проверка данных формы и параметров истории |
| `server/api/monitors*` | Создание, список, пауза, удаление, история и статистика |

`probe.ts` оставлен отдельным: обработка сетевых ошибок и ограничений не мешает читать основной чекер.

## Тесты

```bash
npm test
npm run typecheck
npm run build
npm run test:api
```

`npm test` проверяет аптайм, смену статуса, ограничение конкурентности, адреса, HTTP-ошибки, редиректы, таймауты, размер и обрыв ответа.
`npm run test:api` проверяет реальное API собранного приложения на **временной копии SQLite-базы**. Основная база не очищается. Перед этим нужен `npm run build`.
При подготовке прошли TypeScript, production-сборка, 5 автоматических тестов и 29 проверок API/SQLite.

## Если не запускается

- Проверьте `node --version`: рекомендуется Node.js 24 LTS. На поддерживаемых платформах SQLite-драйвер устанавливается с готовым бинарным модулем; на редких системах может потребоваться сборка драйвера.
- Выполняйте команды из папки с `package.json`, а не из папки `app`.
- После изменения схемы БД повторите `npm install`. Prisma не выполняет сброс данных автоматически; если изменение схемы требует удаления данных, остановитесь и сделайте копию базы.
- Если URL не добавляется, проверьте HTTP(S), публичность адреса и DNS. `localhost` намеренно запрещён.
- Если в браузере сайт открывается, но здесь DOWN, посмотрите ошибку в истории: антибот-защита, TLS, сеть сервера или ограничение размера могут отличаться от обычного браузерного доступа.
