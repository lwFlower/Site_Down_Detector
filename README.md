# SiteWatch

Vue 3 + TypeScript + Vite. Все данные хранятся в браузере через localStorage.

## Запуск

Нужен Node.js 24. Распакуйте архив в новую папку и откройте терминал в папке с package.json.

```bash
npm install
npm run dev
```

Откройте адрес из терминала. После установки для следующих запусков достаточно `npm run dev`.

## Что работает

- Добавление сайтов с названием, URL и интервалом от 30 секунд.
- Пауза, возобновление и удаление мониторов.
- Автоматическое создание демонстрационных результатов при открытой странице.
- Кнопки «Проверить сейчас», «Сымитировать сбой» и «Восстановить» в истории монитора.
- История по 10 записей на странице и аптайм за 24 часа, 7 или 30 дней.
- События при переходах UP → DOWN и DOWN → UP. Одинаковые результаты не создают повторное событие.
- Сохранение после обновления и закрытия браузера.

Результат проверки задаётся переключателем состояния. При добавлении создаётся начальный результат UP. Кнопка сбоя записывает 503 и DOWN, восстановление — 200 и UP. Следующие результаты по расписанию повторяют выбранное состояние.

HTTP-коды в этой версии демонстрационные. Фактические запросы к указанным сайтам не отправляются, время и размер ответа не измеряются. Пока страница закрыта, проверки не выполняются. В фоновой вкладке браузер может замедлять таймер. После открытия создаётся один актуальный результат, пропущенные интервалы не заполняются.

Это статическая демоверсия для публикации интерфейса. Первоначальное требование задания о серверном фоновом чекере и реальных HTTP-измерениях она не выполняет. Если преподаватель проверяет эти пункты, сохраните предыдущую серверную версию для защиты.

## Где хранятся данные

Ключ localStorage — `sitewatch-demo-v1`.

Данные принадлежат конкретному браузеру и адресу сайта. Локальный запуск, GitHub Pages и Vercel имеют отдельное хранилище. У другого посетителя будет собственный список. Существующая SQLite-база в localStorage автоматически не переносится, сайты добавляются заново.

Хранятся последние 500 проверок и 100 событий каждого монитора. Аптайм вычисляется по сохранённым проверкам за выбранный период. Более старые записи удаляются при добавлении новых. В списке событий показываются последние 20 за период.

Очистка данных браузера удалит localStorage. В приватном режиме данные обычно сохраняются только до закрытия приватного окна. Если запись не удалась, приложение показывает ошибку и сохраняет прежнее состояние. Повреждённые данные автоматически не перезаписываются.

Для ручной копии откройте F12 → Application → Local Storage и сохраните значение ключа `sitewatch-demo-v1`.

## GitHub Pages

1. Загрузите содержимое этой папки в корень GitHub-репозитория. Убедитесь, что загружена папка `.github` с файлом `.github/workflows/deploy.yml`.
2. Откройте Settings → Pages → Build and deployment → Source и выберите **GitHub Actions**.
3. Выполните push в ветку `main`. Если ветка называется иначе, измените `branches` в deploy.yml.
4. Откройте Actions и дождитесь успешного workflow. Ссылка появится в Settings → Pages.

Workflow устанавливает зависимости, собирает проект и публикует папку `dist`. Параметр `base: './'` обеспечивает относительные адреса JS и CSS. Главная страница открывается как по адресу домена, так и в подпапке репозитория. Маршрутизатор с отдельными URL страниц не используется.

В архиве есть готовая папка `dist` для размещения на статическом хостинге. Для проверки на компьютере используйте `npm run preview`, прямое открытие index.html как файла не предназначено для запуска модулей браузера.

## Vercel

Для этой версии выбирайте **Vite**, Build Command — `npm run build`, Output Directory — `dist`. Root Directory должна указывать на папку с package.json.

В комплекте `vercel.json` с нужными настройками. Он заменяет старые настройки Nuxt. Если обновляете существующий репозиторий, удалите старые папки `server`, `prisma`, `generated`, файл `nuxt.config.ts` и старые файлы конфигурации. Удобнее сначала разместить новую версию в отдельном репозитории.

## Структура

| Папка | Назначение |
| --- | --- |
| `app/pages` | Главная страница |
| `app/components/monitors` | Форма, список, история, события и кнопки демонстрации |
| `app/components/common` | Общий индикатор статуса |
| `app/composables` | Состояние формы и карточки, браузерный таймер |
| `app/services` | Операции с мониторами, создание результатов и расчёт статистики |
| `app/storage` | Чтение, проверка и сохранение localStorage |
| `app/types` | TypeScript-типы данных |
| `app/utils` | Форматирование даты и размера |
| `app/assets/css` | Оформление |
| `.github/workflows` | Публикация на GitHub Pages |
| `tests` | Проверки сохранения, переходов статуса, статистики и пагинации |

Страница вызывает composable, он вызывает операцию сервиса. Сервис подготавливает данные и сохраняет их через storage-модуль, после успешного сохранения обновляется интерфейс. Ошибка записи оставляет предыдущую версию данных.

Исходные файлы короче 350 строк. package-lock.json создаётся npm автоматически.
